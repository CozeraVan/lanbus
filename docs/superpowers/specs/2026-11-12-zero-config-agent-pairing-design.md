# Lanbus 零配置 Agent 直连配对设计

日期：2026-11-12
状态：已获用户分段批准，待书面规格复核

## 1. 目标

局域网内任一 AI agent 可以直接向本机或其他机器的 AI agent 发起交流与指挥请求。用户不创建、复制或维护 token；被指挥 agent 所在机器的人通过本地确认授予访问权。

目标命令：

```bash
lanbus chat --to mac-agent --message "请介绍你的环境，并给出协作方案"
lanbus run --to windows-agent --cwd "D:\project" --message "检查当前项目并运行测试"
```

正常流程不需要 `lanbus connect`、共同 Hub 或手工密钥。已有 Hub/token/MCP 部署继续兼容。

## 2. 非目标

- 不把局域网视为天然可信网络，不开放匿名命令执行。
- 不用共享密码、默认密码或固定 pairing code 替代人工授权。
- 不在第一版实现跨 Hub 联邦、互联网中继或多跳路由。
- 不删除现有 Hub 模式及其 token 协议。
- 不声称自然语言风险分类可以替代操作系统沙箱。

## 3. 架构选择

采用 Agent/Worker 直连配对。每个 Worker 提供受限配对入口、正式请求入口和仅本机可用的审批入口。Hub 仅保留现有集中管理功能，不是直连模式的信任中心。

一次性数字配对码只作为自动握手失败的备用恢复方式，不进入正常路径。

### 3.1 独立组件

1. **Peer identity**：每安装实例生成长期身份密钥，计算稳定 peer ID 和可展示指纹。
2. **Peer discovery**：扩展现有发现结果，广播/暴露 agent 名称、机器名、直连地址和能力；允许显式 IP:port。
3. **Pairing service**：接收签名、限时的配对申请，只创建 pending 记录，不执行任务。
4. **Local consent**：目标机器的 GUI 或本地 CLI 展示请求并批准、拒绝、撤销；写接口仅监听/接受 loopback。
5. **Grant store**：保存目标端授权和发起端内部会话凭证，POSIX 0700 目录、0600 文件，原子替换。
6. **Direct session**：验证来源身份、授权范围、有效期和防重放数据，建立加密传输。
7. **Direct executor**：在目标 Worker 已批准的 cwd 和能力范围内执行对话或项目任务并返回结果。

## 4. 首次配对流程

1. 发起方按名称发现目标；重名时列出机器名、地址和能力，由用户选择，不取第一个。
2. 发起方生成安装级身份密钥和请求随机数，发送来源机器、agent、公钥/指纹、请求摘要、cwd、申请能力、有效期。
3. 目标端验证格式、来源地址是否在允许网络、有效期、随机数和频率，创建 pending；不读取项目、不调用 agent CLI、不执行命令。
4. 目标机器本地显示请求，用户选择：
   - 持续配对：保存来源身份，后续在授权范围内的请求自动放行。
   - 会话授权：只授权指定来源、目标和会话；空闲 30 分钟、目标重启或用户结束后失效。
   - 拒绝：不发放凭证，记录结果。
5. 用户同时选择最小能力范围：交流/只读，或项目任务。
6. 批准后双方完成认证加密握手；目标返回授权结果，发起方保存内部会话凭证。密钥不出现在 CLI 参数、日志或 UI。
7. 正式请求携带来源身份、授权 ID、短期会话证明和单调请求序号；目标校验后才执行。
8. 首次信任采用人工确认 TOFU；后续身份密钥必须匹配。指纹变化时拒绝自动替换，要求新的本地审批。

## 5. 权限模型

授权由时长、来源身份、目标 Worker、能力集合、cwd 集合和会话约束共同构成。

### 5.1 交流与只读

- 查询 Worker 版本、机器、agent 和已声明能力。
- 在已批准 cwd 内读取项目上下文。
- 参与多轮对话。
- 不允许写文件、安装依赖、管理进程或访问未批准目录。

### 5.2 项目任务

- 包含交流与只读能力。
- 允许在已批准 cwd 内修改文件、运行测试和普通开发命令。
- 新 cwd、目录外写入、删除用户数据、软件安装、系统配置、进程/服务管理和凭据访问需要新的目标端确认。

### 5.3 风险执行边界

自然语言只用于向用户展示请求，不作为授权依据。Worker 根据实际 cwd、命令、文件操作和资源访问执行能力检查；无法判定时默认再次确认。

第一版必须明确进程级权限边界：若底层 agent CLI 自身拥有超出 Worker 限制的权限，项目任务授权不能被视为完整 OS 沙箱。UI 和文档必须展示这一事实，不能以“低风险”字样暗示绝对安全。

## 6. 本地审批安全

- 批准、拒绝、撤销只接受 127.0.0.1/::1 的本机请求，并校验仅存在于本地 UI 进程中的随机审批会话，不依赖可远程读取的固定 secret。
- 远程 pairing 请求不能调用本地审批接口，不能指定自己的审批结果。
- pending 默认 10 分钟过期；目标离线期间入队的旧请求在上线后不得自动执行。
- 限制每来源和全局 pending 数量、请求体大小及申请频率。
- 所有正式请求校验时效、nonce/序号和授权状态，阻止重放。
- 撤销立即删除/禁用授权，旧凭证不能继续使用。
- 日志记录来源 peer ID、权限、审批结果和执行摘要，不记录私钥或会话秘密。

## 7. CLI 与本地交互

发起端：

```bash
lanbus peers
lanbus chat --to PEER --message TEXT [--conversation ID]
lanbus run --to PEER --cwd DIR --message TEXT
lanbus revoke --to PEER       # 删除本侧凭证，不等于目标撤销
```

目标端本机：

```bash
lanbus inbox
lanbus allow REQUEST_ID --pair --scope chat
lanbus allow REQUEST_ID --session --scope project --cwd DIR
lanbus deny REQUEST_ID
lanbus peers --revoke PEER_ID
```

GUI 提供同等操作。审批时显示来源机器、agent、指纹、请求摘要、cwd、能力和时长。

等待、拒绝、超时、权限不足、目标离线、身份变化和重名均返回机器可读错误及简短中文提示。权限不足只能触发目标端新审批，发起端参数不得绕过。

## 8. 兼容与迁移

- 新增 direct peer 协议，不改变现有 Hub Worker 注册、MCP、REST 或数据库协议。
- 保留 `connect` 和现有 token 档案供 Hub 模式使用；直连命令不读取或要求这些 token。
- 未启用直连监听的旧 Worker 不可被直连，发现结果标记 `direct_pairing=false`，不假装配对成功。
- 直连监听默认仅私网/loopback；公网地址默认拒绝，显式启用也不免除目标端审批。
- Python Worker 首先实现完整参考流程；Go Worker 在协议测试对齐后开放对应能力。

## 9. 测试与验收

### 9.1 单元测试

- 身份生成、持久化、指纹匹配和身份变化拒绝。
- 配对申请签名、过期、重放、限流和请求体限制。
- 持续/会话授权、scope/cwd、空闲过期、重启失效和撤销。
- 非 loopback 审批被拒绝，远程请求无法伪造批准。
- 凭证文件权限、原子写入、损坏文件不覆盖、日志不泄密。
- 重名、离线、拒绝、超时、权限不足错误。

### 9.2 真实进程集成

启动两个独立 Worker，清空 token 环境且不启动共同 Hub，完成：

1. 默认发现目标。
2. 发起交流，确认目标尚未执行。
3. 目标本机选择持续配对并完成对话。
4. 第二个 Worker 选择会话授权，完成项目测试任务。
5. 越权 cwd 需要新审批。
6. 会话重启后失效；持续配对撤销后立即拒绝。
7. 伪造远程审批、重放请求和替换身份均失败。

Python/Go 实现通过相同协议契约。真实 macOS 跨机验证需目标机器本地人工确认；在尚未取得该确认前，不宣称真实跨机执行成功。

## 10. 完成标准

- 用户从全新安装开始，不配置 token 即可发现、申请、经目标本地批准后完成交流和任务。
- 目标用户可以选择持续配对或会话授权，并限制 scope/cwd。
- 未批准、已过期、已撤销、重放或身份异常请求均不执行。
- 现有 Hub 模式回归测试保持通过。
- 文档清楚描述安全边界和真正需要人工操作的唯一步骤：目标端审批。
