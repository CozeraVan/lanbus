# Python 与 Go Hub 状态一致性优化设计

## 目标

在不改变 MCP、REST、数据库公共结构和默认部署方式的前提下，修复 Python 与 Go Hub 在重试配置、任务状态转移、租约恢复、Host 校验及文本截断方面的行为差异和竞态。

## 范围

本轮仅修改两套 Hub 及直接相关测试，不重构 Worker、发现器、浏览器、聊天和桌面端，不引入第三方 Python 依赖。

## 设计

### 1. 零值配置

`max_retry` 与 `max_recoveries` 只在参数缺失时采用默认值。显式传入 `0` 表示禁止重做或禁止租约恢复，并必须在任务创建、审批打回和租约恢复阶段保持一致。负数按 `0` 处理，避免产生不可理解的状态。

### 2. 审批与打回

`approve` 和 `rework` 只接受 `submitted` 状态。状态变更使用带当前状态条件的数据库更新，并根据受影响行数判断操作是否仍然有效，避免并发的取消、提交和审批相互覆盖。

打回时保留并累计历史反馈，清除上一轮的结果、验证输出、差异、退出码、组合提示词和产物记录。重试次数耗尽后进入 `failed`，不再重新排队。

### 3. 租约与日志竞态

任务恢复只作用于仍为 `claimed` 或 `running` 且 Claim Token 未变化的记录。进度续租和日志元数据更新同时校验任务 ID、Worker、Claim Token 与活动状态，防止旧 Worker 在网络分区或重新分配后续租新轮次。

日志插入继续使用 `(task_id, seq)` 幂等约束；数据库错误不得被当作成功响应吞掉。

### 4. Host 安全校验

Go Hub 对需要认证的接口执行与 Python Hub 一致的 Host 检查：允许环回主机名、配置白名单以及 IPv4／IPv6 字面量，正确处理带端口和方括号的形式。非法 Host 返回 HTTP 403，认证失败仍返回 HTTP 401。健康检查与公开 UI 的现有公开语义不变。

### 5. UTF-8 截断

Go Hub 的日志、结果、差异和提示词截断不得切断 UTF-8 编码序列。达到字节上限时回退到最近的完整字符边界，保持现有限额不变。

## 错误处理

无效状态转移返回包含当前状态的错误，不发送虚假的成功事件。条件更新影响行数为零时重新读取任务并返回最新状态。数据库错误返回给调用方，不静默忽略关键状态写入失败。

## 测试

- Python：覆盖显式零值、非提交状态打回、反馈累计、证据清理、取消与审批竞争及非法 Host。
- Go：覆盖默认值与零值、合法与非法 Host、状态转移条件、恢复条件和 UTF-8 截断。
- 双实现：沿用现有协议测试，并增加相同输入下的关键状态行为对比。
- 验证：运行 Python 全量测试、Go 全量测试与静态检查；若本机缺少 Go 工具链，则在工作区使用隔离工具链完成验证，不修改系统环境。

## 非目标

不调整默认 Token 策略，不修改任务优先级算法，不改变已有 API 字段，不引入新的任务状态，不开展与上述问题无关的大型重构。
